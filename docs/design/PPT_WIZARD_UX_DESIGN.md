# PPT 탭 UX 재설계 — 4단계 위저드 (확정)

- 작성일: 2026-07-22
- 대상 구현 파일: [src/tabs/pptx.py](../../src/tabs/pptx.py)
- 확정 목업: [client/dev/pptx_wizard_mock.html](../../client/dev/pptx_wizard_mock.html) — 정적 HTML, 브라우저로 직접 열어서 각 단계 클릭하며 확인
- 상태: **목업 확정(lock). 이 문서 기준으로 구현 진행.**
- 이전 설계서 [PPT_FLOW_UX_DESIGN.md](PPT_FLOW_UX_DESIGN.md) (2026-07-02, 흐름 탭 패턴 카드형)는 이 문서로 대체한다. 폐기.

## 1. 배경

기존 PPT 탭(카드 2열 나열: 진행상태/소스선택/변환설정)은 다음 문제가 있었다.

1. 4개 카드가 화면에 동시에 늘어서서 산만하고, 각 카드 내부 정보 밀도가 낮음.
2. "확장" 단계가 실제로는 아무 처리도 하지 않는 빈 개념이었음 — 콘텐츠 부족 문제의 원인.
3. "디자인" 결과물의 실제 시각 품질이 낮음(하드코딩 한글 라벨, 폰트 강제 적용 등은 별도 버그로 이미 수정됨) — 이번 재설계는 템플릿을 인터넷에서 가져와 쓸 수 있게 해서 시각 품질 문제를 완화.

## 2. 최종 구조 — 4단계 위저드

카드 나열 대신 **상단 스텝퍼 + 단일 포커스 패널 + 우측 사이드바(단계별로 내용이 바뀜) + 하단 진행 요약 스트립** 구조로 전환한다.

```
[상단바: PPT · DECK CONSOLE + EXPORT READY 배지]
[스텝퍼: ①소스 ②확장 ③설계 ④렌더 — 클릭하면 해당 단계로 이동]
┌─────────────────────────────┬──────────────┐
│  포커스 패널 (현재 단계 내용)   │  우측 사이드바  │
│                               │ (단계별 내용 다름)│
└─────────────────────────────┴──────────────┘
[진행 요약 스트립: 4칸, 각 칸 "편집" 링크로 해당 단계 이동]
[하단 액션: 이전 / 다음]
```

우측 사이드바는 **①②③ 단계에서는 "생성 설정"(언어·페이지 수·LLM 모델), ④ 단계에서는 "문제 유형" 패널로 바뀐다.** 목업의 `SIDES` 배열이 이 전환을 담당한다 (`SIDES[0..2]` = 생성 설정, `SIDES[3]` = 문제 유형).

## 3. 단계별 상세

### ① 소스

- 안내문: "PPT로 만들 원본을 고릅니다. 직접 입력하거나, 파일을 올리거나, archive · docs/system에 이미 있는 자료를 골라도 됩니다."
- 소스 탭: 직접 입력 / 파일 업로드 / archive · N건 / docs/system · N건 — 기존 로직(`_list_archive_content_md`, `_list_docs_md`, `_render_doc_picker`) 그대로 재사용.
- 우측 "생성 설정": 언어 선택(신규), 페이지 수(자동/5/10/15, 신규), LLM 모델(기존 `_ollama_models()` 재사용).
- 이 3개 값은 ②확장 단계의 LLM 변환 호출에 그대로 전달된다.

### ② 확장 — LLM 변환 (신규 처리 단계)

기존에는 존재하지 않던 실제 처리 단계. **①에서 고른 소스 + 언어/페이지수/모델 설정을 LLM에 넣어, 아래 하네스 규칙을 지키는 마크다운으로 재작성한다.**

하네스 규칙 (LLM 프롬프트에 강제로 포함시켜야 함):
1. `lang: <언어코드>` 지정
2. 페이지마다 `title` / `description` / `body_type` / 본문 필드
3. `body_type`은 **서술식 / 요약식 / 표형식 / 도형형식** 중 하나 — 페이지 내용을 보고 LLM이 스스로 판단해서 지정 (고정값 아님)

출력 예시 (목업의 `.expand-box` 내용 그대로):
```
lang: ko

## page 1
title: IRIS 주간 보고
description: 2026-06-20 주간 처리 현황 요약
body_type: 요약식
---
- documents **1,304** 행 처리
- chunks **5,231** 청크 생성

## page 2
title: 처리 현황 상세
description: 문서 · 청크 처리량 비교
body_type: 표형식
---
| 항목 | 값 |
|---|---|
| documents | 1,304 행 |
| chunks | 5,231 청크 |
```

이 마크다운이 ③설계 단계 입력이 된다. "재생성" 버튼으로 같은 소스를 다시 LLM에 넣어 재변환 가능.

### ③ 설계 (기존 "변환 설정" 대체, Marp 옵션 제거)

- **Marp 엔진 선택지는 삭제.** 디자인 엔진(LLM 슬라이드 설계 → HTML 템플릿 렌더링) 하나만 사용.
- 템플릿 갤러리: 내장 템플릿(iris 다크/라이트/미니멀) + **URL/검색어로 인터넷에서 템플릿을 가져오는 입력창과 "가져오기" 버튼.** 가져온 템플릿은 같은 그리드에 "가져옴" 배지와 함께 추가되어 동일하게 선택 가능.
  - 이번 구현 범위에서는 "가져오기"가 실제 크롤링/변환까지 할지, 아니면 UI만 두고 기능은 스텁으로 남길지 **VSCode 에이전트가 구현 착수 전 확인 필요** (아래 6절 참고).
- 마스터 스타일 섹션(신규, PPT 슬라이드 마스터 개념): 제목 폰트/크기/색상, 페이지 번호 위치, 로고 고정 표시. **템플릿을 바꿔도 여기서 손댄 값은 유지된다** — 즉 템플릿 선택과 마스터 스타일은 별도 상태로 관리해야 함(템플릿 변경 시 마스터 스타일 리셋하지 않음).
- 나머지 설정(출력 형식 PDF/PPTX, 레이아웃 밀도, 페이지 번호, exports 저장, "설계 단계에서 다른 LLM 쓰기")은 라벨+컨트롤이 붙는 컴팩트 flex-wrap 행(`.compact-row`/`.compact-field`)으로 배치 — 2열 그리드로 여백을 낭비하지 않는다.
- "설계 단계에서 다른 LLM 쓰기" 토글: 기본 OFF(②확장과 동일 모델 공유). ON일 때만 별도 모델 선택 노출(목업에는 토글만 있고 선택 UI는 아직 없음 — ON 시 셀렉트 추가 필요).

### ④ 렌더 — 결과 리뷰 · 부분 재생성 (신규)

렌더는 "진행률 보여주고 끝"이 아니라 **결과를 리뷰하고 문제를 잡는 버그픽스 단계**로 설계했다.

- 완료 후 페이지별 썸네일 카드 그리드. 각 카드는 체크박스로 선택 가능(다중 선택), 클릭 시 토글.
- **우측 사이드바가 이 단계에서만 "문제 유형" 패널로 바뀐다** (생성 설정 아님):
  - 언어 선택 오류
  - 내용 밀도 오류
  - 글자 겹침 오류 (실제로 가장 많이 발생하는 결함 — 기본 체크)
  - 페이지 형식 오류 (예: body_type=표형식으로 지정했는데 실제로는 요약식으로 렌더링됨)
  - 안내문: "왼쪽에서 선택한 페이지에 표시된 문제만 골라 그 부분에 집중해서 다시 생성합니다."
- 하단 액션: "표시한 문제로 재생성" / "전체 재생성" / "PDF 다운로드".
- 동작 정의: 카드 선택(좌) × 문제 유형 체크(우)의 조합이 재생성 요청의 스코프가 된다 — 선택된 페이지만, 체크된 문제 유형에 해당하는 부분만 다시 그리도록 LLM/렌더러에 지시.

## 4. Streamlit 매핑 메모

- 단계 상태: `st.session_state["pptx_wizard_step"]` (0~3)로 관리. 스텝퍼 클릭 = 해당 인덱스로 set + rerun.
- 우측 사이드바 전환은 스텝 값에 따른 조건 분기(`if step == 3: ... else: ...`)로 구현 — 목업의 `SIDES` 배열과 동일한 개념.
- 기존 `_stage_card`, `_render_strip` 등 "카드 4개 가로 나열" 렌더 함수는 이번 구조에서 더 이상 쓰이지 않음 — 스텝퍼 렌더 함수로 교체.
- `_generate_marp` 관련 코드/옵션은 제거 (엔진 단일화).
- `_generate_design`은 유지하되, 입력이 이제 ②확장 단계에서 나온 "하네스 스키마 마크다운"이 된다 — 프롬프트에 언어/페이지수 규칙 반영 필요.
- CSS는 기존 `hub_ui.css` PPT 탭 전용 블록을 이번 구조에 맞게 다시 작성. 목업 `<style>` 블록의 클래스명(`.stepper`, `.step`, `.panel`, `.side`, `.tpl-grid`, `.master-section`, `.compact-row`, `.render-card`, `.issue-legend` 등)을 그대로 가져다 써도 됨 — 색상 토큰은 프로젝트의 진단툴 팔레트(`--ch-1`~`--ch-7`)와 이미 일치시켜 놨음.

## 5. 이번 구현 범위가 아닌 것 (건드리지 않음)

- PDF/PPTX 실제 렌더링 파이프라인 자체(`pptx_export.py` 등)의 도형/텍스트박스 방식은 유지.
- 언어 감지(`schema.py: detect_deck_lang`) 로직은 이미 반영되어 있음 — 그대로 재사용.

## 6. 구현 착수 전 VSCode 에이전트가 확인해야 할 것

1. "템플릿 가져오기"(URL/검색어 → 인터넷에서 템플릿 수집) — 이번 패스에서 실제 동작까지 구현할지, UI만 두고 기능은 no-op/TODO로 스텁할지.
2. ②확장 LLM 호출과 ③설계 LLM 호출을 같은 함수로 통합할지, 별도 함수로 유지하되 모델 파라미터만 공유할지.
3. "문제 유형" 재생성이 실제로 부분 재생성(해당 페이지만 다시 렌더)까지 이번 패스에서 구현할지, 우선 전체 재생성으로 대체할지.
